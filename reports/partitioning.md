# Partitioning: pruning and retention

`orders` and `audit_logs` copied into monthly range partitions (schema `part`, see
`sql/partitioning/`) and compared with the plain tables, first with TopFlow's own
indexes and then with the casebook's indexes. The partitioned tables carry the same
indexes as the tuned plain tables.

- Generated by `./lab partition` on 2026-09-26 01:43 UTC.
- Data: SCALE=1000000 (about 1,000,000 order lines), history anchored at 2026-09-26 01:00:00.
- Server: PostgreSQL 18.6 (Debian 18.6-1.pgdg13+2).
- Environment: Docker Desktop (Docker 29.8.0), 16 CPUs and 7.4 GiB of memory for all containers on Windows NT 10.0 build 26200 (Git Bash); pg1 limited to 1g with shared_buffers 256MB; the machine was shared with other parallel builds during this run.
- Timings: pending a measured run. This was a functional run: every count, size, plan and check below is measured, but durations were not recorded (see docs/benchmarking.md).
- Rows copied: part.orders 200,000, part.audit_logs 1,000,000.

## Retention: removing the oldest full month of audit entries

| Method | Rows removed | WAL written |
| --- | ---: | ---: |
| `DELETE` on the plain table | 42,466 | 7,535,391 bytes |
| `DETACH PARTITION` (audit_logs_p2024_10) | 42,466 | 29,144 bytes |

The DELETE also leaves every removed row as a dead tuple for VACUUM, and its index
entries until VACUUM cleans them; a detached partition is a table of its own that can
be dumped, moved to cheaper storage or dropped in one step.
